# Split SYSTEM.PASCAL core reconstruction

The core contains 39 p-code procedures. Procedures 1–37 and 39 load in the
3,124-byte region at `$F248`; procedure 38 loads in a separate 170-byte region
at `$BC72`. Whole-region emulator captures in `reference/runtime-init.json`
establish both placements. The dictionary for all 39 procedures remains in the
core. There is no second dictionary in the procedure-38 fragment.

`tools/system_core_source.py` parses the actual dictionary using these load
addresses, then concatenates core and fragment for decoding. It adjusts only the
procedure-38 offsets and dictionary address expression. Both load addresses are
even, so the concatenated representation preserves p-code alignment behavior.

At core file offset `$0BE6`, the procedure-38 dictionary word is `$4114`. Its
loaded address is `$FE2E`, and subtracting `$4114` gives the captured attribute
address `$BD1A`. That is `$BC72 + $00A8`. In the concatenated source, the fragment
starts at `$0C34`, so its attributes are labeled `$0CDC`; a `$420A` address delta
makes the source expression reproduce the same word. The decoder explicitly
checks this expression against the stored displacement.

The existing `system_entry.s` retains ownership of procedure 1's first 36 bytes.
`system_core.s` starts at source offset 36 and emits the remaining core bytes
followed by the fragment, totaling 3,258 newly reconstructed output bytes. Its
constant label for procedure-1 attributes refers to the existing component;
preparation checked that component against the complete core prefix. The normal
build checks both component hashes independently.

All 3,294 core/fragment bytes are classified: 1,891 instructions occupy 2,667
bytes; the rest are procedure metadata, dictionary words, 62 branch-table bytes,
19 alignment bytes, and 76 inline string bytes. The fragment's offsets in the
listing are concatenated-file offsets, not its runtime addresses.

One additional statically reviewed code root occurs at `$03BD` in procedure 13.
It is UJP +12 to `$03CB`, immediately following the unconditional UJP at `$03BB`.
The target is reachable independently from the procedure's ordinary roots; the
extra instruction is not. This is the same retained conditional-join pattern
as the cases in [pcode-unreachable-branches.md](pcode-unreachable-branches.md).
It remains represented as an instruction with unproven runtime reachability.

Reproduce a listing from extracted core/fragment components with:

```sh
python3 tools/system_core_source.py build/system_core.bin \
  build/system_fragment.bin --source build/system-core-review.s
```

Those two inputs are maintenance extracts, not normal build dependencies. The
adoption mapping records their disk locations: disk-1 block 252 onward and the
first 170 bytes of block 259. All generated bytes and both full disks match the
originals. A synthetic split-layout test rejects an incorrect address delta.
